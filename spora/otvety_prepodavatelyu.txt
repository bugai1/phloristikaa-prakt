ШПОРА ДЛЯ ОТВЕТОВ ПРЕПОДАВАТЕЛЮ

1. Чем response.json() отличается от json.loads(content)?
response.json() разбирает внешний JSON, который вернул HTTP API. json.loads(content) отдельно разбирает текст внутри message.content, если модель поместила туда JSON.

2. Почему успешный HTTP-статус ещё не означает, что ответ подходит приложению?
Статус 2xx означает, что HTTP-запрос выполнен успешно. Но внутри может быть неправильный JSON, отсутствующие поля, неверные типы или недопустимые значения.

3. Чем JSON mode отличается от JSON Schema / Structured Outputs?
JSON mode просит модель вернуть синтаксически корректный JSON. JSON Schema / Structured Outputs дополнительно задаёт структуру и ограничения полей. Проверка результата в коде всё равно нужна.

4. Почему нужно задать timeout?
Чтобы программа не ждала сетевой ответ бесконечно и могла сообщить пользователю об ошибке.

5. Что делать, если API вернул 401, 429 или 500?
401 — проверить API-ключ. 429 — учесть лимит и попробовать позже. 500 — проблема на стороне сервера; сообщить об ошибке и повторить запрос позже, если это уместно. Не повторять запрос бесконечно.

6. Почему нельзя сохранять API key в .py или отправлять в Git?
Ключ является секретом: другой человек может его получить и использовать. Ключ хранят в локальном .env, а .env добавляют в .gitignore.

7. Чем внешний JSON отличается от JSON внутри content?
Внешний JSON содержит структуру ответа API, например choices и message. Поле content — строка, в которой может лежать второй JSON. Поэтому их разбирают двумя отдельными операциями.

8. Зачем нужна валидация?
Она проверяет, что обязательные поля существуют, типы правильные, а category и priority имеют допустимые значения. Некорректный ответ не должен сохраняться как успешный.

9. Что делает mock-режим?
Использует заранее подготовленную локальную логику без сетевого запроса и API-ключа. Так можно проверить приложение без расходов и интернета.

10. Для чего нужны .env.example и .gitignore?
.env.example показывает, какие настройки требуются, без настоящих секретов. .gitignore запрещает добавлять в Git локальный .env, виртуальное окружение и файлы результатов.

11. Какие обязательные функции есть в проекте?
load_config, build_payload, extract_content, parse_model_json, validate_result, call_llm, save_result и main.

12. Что делает validate_result()?
Проверяет наличие category, priority, summary, tags и requires_human, затем проверяет типы и допустимые значения.

13. Почему нельзя использовать except без типа исключения?
Так можно скрыть ошибки, которые программа не должна перехватывать. Лучше отдельно обрабатывать ожидаемые ошибки сети, HTTP и JSON.

14. Что делает timeout=30?
Ограничивает ожидание ответа сервера 30 секундами.

15. Как запускаются тесты?
Командой: python -m unittest discover -s tests -v

16. Как запускается mock-режим?
Командой: python app.py --mock "С меня дважды списали оплату за один заказ"

17. Как запускается реальный режим?
Нужно заполнить локальный .env и выполнить: python app.py --real "Текст обращения". Настоящий ключ нельзя отправлять в чат или Git.

18. Почему результат сохраняется только после валидации?
Чтобы неправильные данные не были помечены как validated и не использовались дальше как корректный результат.

19. Какие поля сохраняются в result.json?
request_id, model, status и поля проверенной классификации. API-ключ и Authorization header не сохраняются.

20. Что делает extract_content()?
Безопасно извлекает строку choices[0].message.content и выдаёт понятную ошибку, если структура ответа неправильная.
